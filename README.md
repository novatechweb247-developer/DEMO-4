# Foundation Demo Site

Build the MASTER PUBLIC WEBSITE DEMO for a reusable website system. This is the MASTER TEMPLATE — not for a real client. Do NOT use real business information; do NOT invent a real company, address, phone number, email, social media account, reviews, prices, or business claims. Use polished DEMO content only. The purpose is a nearly finished professional business website that can later be duplicated for different businesses: MASTER DEMO → Duplicate/Import → Provide real business details → Replace demo content → Replace images → Customize services/pages → Connect Admin Center → Final client website. The architecture must be reusable and easy to customize, so future AI-assisted customization mainly replaces content and media rather than rebuilding structure.

CORE OBJECTIVE: A premium, modern, responsive multi-page business website that already feels like a finished professional client website. It must NOT look like a coding demo, developer portfolio, template preview, dashboard, unfinished wireframe, or generic AI-generated website. All business information must clearly be DEMO content.

ARCHITECTURE: CONTENT-DRIVEN. Do not scatter business information across dozens of files. Create a clear centralized structure for demo content organized conceptually around: business information, navigation, hero slides, homepage sections, services, gallery, about content, contact information, social links, footer, SEO metadata. A future AI assistant should be able to receive Business Name, Phone, WhatsApp, Email, Address, Services, About info, Social links, Images etc. and replace demo content without rebuilding the website architecture. Use reusable layouts and reusable UI components, clean asset organization, responsive CSS, lightweight JS only where needed. No unnecessary frameworks or over-engineered architecture. Easy for another AI assistant to modify later.

PAGES (real routes, no dead links): / , /about , /services , /gallery , /contact . Reusable: Header, Navigation, Mobile navigation, Footer, Buttons, Section headings, Cards, Image containers, CTA sections, Page hero/banner, Breadcrumb/page heading where appropriate.

DESIGN: Premium modern business aesthetic, intentionally neutral so the template can later adapt to furniture, fashion, salons, restaurants, hotels, event centers, logistics, service businesses, stores, creative and professional businesses. Strong typography, excellent spacing, generous whitespace, premium image presentation, rounded corners where appropriate (do not overdo — not every element a pill, circular controls only where they make sense), refined buttons, subtle shadows, layered sections, modern cards, polished hover states, smooth transitions.

RESPONSIVE (critical): Mobile-first but excellent on small phones, normal phones, large phones, tablets, laptops, desktops. Properly redesign spacing and layout behavior at smaller breakpoints — do not simply shrink the desktop design. Check header, hero, buttons, cards, image grids, text blocks, navigation, footer, forms, gallery, section spacing. No horizontal overflow, broken layouts, text overlapping, buttons extending outside containers, distorted images, excessive empty space, or tiny unreadable text.

HEADER/NAV: Premium responsive header. Desktop: logo/business name, Home, About, Services, Gallery, Contact, primary CTA. Mobile: clean simple professional reliable mobile menu — no strange text pop-out animations, excessive animations, oversized menus, or broken hamburger interactions. Header visually consistent across pages.

HOMEPAGE: complete and premium: 1) Hero 2) Intro/About preview 3) Services preview 4) Featured/gallery preview 5) Why choose us / value section 6) CTA section 7) Contact/location preview 8) Footer. Every section has a clear visual purpose; homepage must not feel empty.

HERO: EXACTLY 3 HERO SLIDES — not 2, not 4, not 5. Structural demo slides with polished demo copy. Each slide supports image, title, subtitle/description, primary button, optional secondary action. Built so these three slides can later be controlled independently by a future Admin Center; do not hardcode around a single hero image; do NOT create an "add slide" system in the public demo — the structure is permanently designed around three slides. Hero images may be placeholders/approved demo imagery initially; use a clean image abstraction so future copies replace images easily; images maintain aspect ratio, use proper object-fit, never distort, work on mobile and desktop. Hero animation subtle and premium: fade transitions, subtle scale, subtle horizontal movement. Avoid excessive zoom, flashy effects, distracting text animations, aggressive parallax. If automatic rotation is implemented: rotate automatically, visible slide indicators/dots, allow manual slide selection, manual selection resets the timer, automatic rotation then resumes. Demo hero text like "Designed for the Way You Live" or another polished generic headline. Do NOT use fake claims ("Number one in Nigeria", "Trusted by 10,000 customers", "20 years of experience") unless clearly presented as placeholder/demo text. The demo must never accidentally make false claims for a future client.

HOMEPAGE INTRO: eyebrow like "ABOUT OUR BUSINESS", large heading, short professional paragraph, CTA "Discover More", strong supporting image — clearly generic/demo content.

SERVICES SECTION: professional showcase with several DEMO services, e.g. Premium Consultation, Custom Solutions, Professional Service, Quality Products, Personalized Support, Reliable Delivery — demo placeholders. Reusable service structure: each service supports title, short description, icon/image if appropriate, optional link. Not hardcoded into one component.

FEATURED/GALLERY SECTION: premium visual showcase with several demo images/placeholders; layout supports large featured image, supporting images, responsive grid, hover interaction, clean spacing. Images never stretch or distort. Structure must later support real client images.

WHY CHOOSE US: polished value section with generic demo benefits (Attention to Detail, Quality First, Personal Service, Reliable Experience). No fake numerical statistics. Avoid fake testimonials unless explicitly labeled as demo content.

CTA SECTION: strong final CTA, e.g. "Let's Create Something Great", supporting demo text, buttons "Get in Touch" / "Contact Us". Visually separates itself from surrounding content.

ABOUT PAGE /about: page hero, introduction, story section, values, visual section, CTA. Demo content; looks complete, not placeholder.

SERVICES PAGE /services: page hero, service grid, detailed service sections, CTA. Services generated from the centralized content structure where practical; do not repeat unrelated hardcoded data.

GALLERY PAGE /gallery: page hero, professional gallery grid, large image presentation, responsive layout; optional category/filter structure ONLY if genuinely useful — no unnecessary complicated filtering. Visually strong.

CONTACT PAGE /contact: page hero, contact information, phone, email, location, WhatsApp CTA, social links, enquiry/contact form UI, map/location area placeholder if appropriate. ALL contact info is DEMO, clearly generic placeholder data. Form has proper frontend structure and validation-ready fields; the final backend submission system comes later in the Admin/persistence phase. Do NOT pretend an enquiry was permanently submitted if no backend persistence exists yet.

FOOTER: business/demo name, short description, navigation, services, contact information, social icons, copyright, CTA. Clean, not overloaded.

SOCIAL MEDIA: reusable social-link components for Instagram, Facebook, TikTok, WhatsApp with recognizable icon treatments. Do not invent real social handles; use demo/placeholder values easily replaced later.

IMAGE SYSTEM: clean image abstraction — content/data → image reference → public component. The image layer should make it easy later to connect Admin Center → Persistent Storage → Database reference → Public website. Do NOT build a separate Media Library. Do NOT build an Admin Center yet. This phase is the PUBLIC DEMO only.

FUTURE ADMIN COMPATIBILITY: structure so a future Admin Center can control Hero Slides 1–3, Homepage editorial content, Homepage images, Services, Gallery, About content, Contact information, Social links, Footer content. Use centralized data structures rather than burying everything in page templates.

SEO FOUNDATION: reusable SEO metadata support; each page defines title, description, optional keywords, Open Graph title/description/image where practical. DEMO metadata only; no fake ranking claims, no keyword stuffing.

PERFORMANCE: reasonably lightweight, no unnecessary libraries, optimized image rendering, lazy loading for non-critical images where appropriate, smooth animations on mobile. Do not sacrifice performance for visual effects.

ACCESSIBILITY: semantic HTML, proper headings, alt text structure, accessible buttons, keyboard-friendly controls, readable contrast, form labels. Do not rely only on color to communicate information.

ANIMATIONS: premium feel — subtle fade, slide, scale, hover, reveal. NO excessive bouncing, constant movement, flashy transitions, exploding/pop-out text, animations that interfere with reading, or unnecessary loading screens. The website should feel expensive, not chaotic.

AVOID GENERIC AI TEMPLATE LOOK: no giant text everywhere, excessive gradients, random glassmorphism, excessive cards, excessive rounded containers, generic purple/blue SaaS styling, huge empty spaces, repeated sections saying the same thing, fake statistics, fake testimonials, meaningless buzzwords, unnecessary animations. Design intentionally.

DEMO CONTENT RULE: everything is DEMO content — realistic but generic. No real Nigerian business names, real phone numbers, real email addresses, real addresses, real client info, copyrighted brand assets, fake customer reviews presented as real, fake certifications, fake awards, fake statistics. Use clearly replaceable demo information.

CODE QUALITY: clean and organized — reusable components, reusable layouts, centralized data, descriptive names, simple conventions, minimal duplication. Avoid unnecessary abstraction and over-engineering.

DO NOT BUILD YET: no Admin authentication, admin dashboard, CMS, database management UI, media library, booking CRM, advanced permissions, or complex backend workflows — keep the architecture compatible with those future systems.

FINAL QUALITY CHECK before finishing: HOME — hero works, exactly 3 slides, slider controls work, auto rotation works if implemented, mobile and desktop hero work, all homepage sections work. ABOUT/SERVICES/GALLERY/CONTACT — pages load, layouts complete, images display with no distortion, form UI works, no fake successful submission message, responsive. GLOBAL — navigation works, mobile menu works, footer works, no broken links, no horizontal overflow, no console-breaking errors, no missing routes, no placeholder lorem ipsum, no fake real-world business claims.

MOST IMPORTANT FINAL RULE: this project is the FOUNDATION — a future business site gets created primarily by replacing business details, demo copy, hero images, gallery images, services, contact details, social links, colors/branding, adding/removing industry-specific sections only when required, then connecting the Admin Center and persistent database. Core architecture stays reusable. Build a polished, production-quality PUBLIC WEBSITE DEMO that can serve as the foundation for many future client websites. Do not rush the Admin Center; do not over-engineer the backend; focus on making the PUBLIC WEBSITE exceptionally polished, reusable, responsive, structured, and easy to customize.
